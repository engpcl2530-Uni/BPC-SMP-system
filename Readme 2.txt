### 📄 2. ไฟล์ `Readme2.txt` (สำหรับพี่ๆ วิศวกรสาย GAS | Google Appscript )
*(สร้างไฟล์ `.txt` ธรรมดา เพื่อใช้อ่านง่ายๆ เป็นคู่มือฉบับย่อให้ทีมงานครับ)*

```text
=========================================================
คู่มือแนะนำโครงสร้างระบบ (ฉบับเร่งด่วนสำหรับทีมวิศวกร GAS)
=========================================================
สวัสดีครับพี่ๆ เอกสารนี้จัดทำขึ้นเพื่ออธิบายโครงสร้างของระบบ SMP / CMMS แบบย่อ 
เพื่อให้พี่ๆ ที่คุ้นเคยกับ Google Apps Script (Code.gs) สามารถทำความเข้าใจ
และดูแลระบบ Frontend ต่อได้อย่างรวดเร็วครับ

ระบบนี้ถูกเขียนขึ้นด้วยแนวคิด "Separation of Concerns (SoC)" 
หรือการแยกหน้าที่ของไฟล์ออกจากกันอย่างชัดเจน เพื่อให้ง่ายต่อการแก้ไขครับ

[ 1. โครงสร้างไฟล์ Frontend (ฝั่งหน้าเว็บ) ทำงานอย่างไร? ]
หน้าเว็บที่เราเห็นบน GitHub Pages ถูกแยกออกเป็น 3 ไฟล์หลัก:
  1) index.html -> เป็น "โครงสร้าง" (ตาราง, กล่องข้อความ, ปุ่มกด) 
  2) style.css  -> เป็น "ความสวยงาม" (สีปุ่ม, ขนาดฟอนต์, แอนิเมชัน)
  3) script.js  -> เป็น "สมองกล" (จัดการเวลาคนคลิกปุ่ม, คำนวณค่า, และคุยกับเซิร์ฟเวอร์)

* ข้อดีคือ: ถ้าพี่อยากแก้สีปุ่ม ไปไฟล์ css / ถ้าอยากเพิ่มช่องกรอกข้อความ ไปไฟล์ html / ถ้าจะแก้ระบบบันทึก ไปไฟล์ js

[ 2. Frontend คุยกับ Google Apps Script ได้ยังไง? ]
พี่ๆ จะคุ้นเคยกับฟังก์ชัน doPost(e) และ doGet(e) ใน Code.gs ใช่ไหมครับ?
ฝั่ง Frontend จะสื่อสารกับ Code.gs ผ่านไฟล์ "script.js" ครับ

ในไฟล์ script.js บรรทัดบนสุดจะมีตัวแปร:
const API_URL = "https://script.google.com/macros/s/..../exec";

เมื่อผู้ใช้กดปุ่ม "บันทึก" โค้ดใน script.js จะแพ็คข้อมูลทั้งหมดเป็นก้อน JSON
แล้วใช้คำสั่ง fetch(API_URL, { method: 'POST', body: JSON.stringify(data) })
ยิงข้อมูลไปหา doPost(e) ฝั่ง Google Apps Script ครับ 

* สำคัญมาก: ทุกครั้งที่พี่ๆ แก้ไข Code.gs ฝั่ง Apps Script และทำการ "Deploy -> New Deployment" ใหม่ 
พี่ต้องนำลิงก์ Web App URL ตัวใหม่ มาเปลี่ยนในตัวแปร API_URL ในไฟล์ script.js เสมอนะครับ ไม่งั้นเว็บจะบันทึกไม่ได้!

[ 3. แผนที่การหา Bug (พังตรงไหน ไปแก้ไฟล์ไหน?) ]
เพื่อความรวดเร็วในการแก้ปัญหา ให้ดูอาการตามนี้ครับ:
- อาการ: ปุ่มเพี้ยน, ข้อความล้นกรอบ, อยากเปลี่ยนสี 
  >> ไปแก้ที่ไฟล์: style.css หรือเพิ่มคลาสใน index.html

- อาการ: เพิ่มตัวเลือกใน Dropdown, เพิ่มช่องให้กรอกข้อมูล
  >> ไปแก้ที่ไฟล์: index.html (และไปเพิ่มตัวแปรดักรับค่าใน script.js)

- อาการ: กดปุ่มแล้วไม่เกิดอะไรขึ้น, ค้นหาข้อมูลไม่เจอ, โหลด Excel ไม่ได้ 
  >> ไปแก้ที่ไฟล์: script.js (ลองเปิด Chrome Developer Tools (F12) ดูแถบ Console จะเห็น Error ชัดเจนครับ)

- อาการ: ระบบขึ้นว่าเชื่อมต่อสำเร็จ แต่ข้อมูลไม่ลง Google Sheet หรือลงผิดคอลัมน์
  >> ไปแก้ที่ไฟล์: Code.gs (Google Apps Script ฝั่ง Sheet)

[ 4. ทริคการอัปเดตเว็บให้เห็นผลทันที (Cache Busting) ]
บ่อยครั้งที่เราแก้โค้ด script.js หรือ style.css ใน GitHub แล้ว แต่เปิดมือถือมาหน้าเว็บยังเป็นแบบเก่า!
สาเหตุเพราะมือถือจำไฟล์เก่าไว้ (Cache)

วิธีแก้: เข้าไปที่ไฟล์ index.html เลื่อนไปบรรทัดที่มีการเรียกไฟล์ เช่น:
<script src="script.js?v=1.0"></script>
ให้พี่เปลี่ยนตัวเลขด้านหลังเป็น ?v=1.1 หรือ ?v=1.2 ไปเรื่อยๆ 
ระบบจะรู้ทันทีว่าเป็นไฟล์ใหม่ และบังคับโหลดให้ผู้ใช้งานทุกคนทันทีครับ
